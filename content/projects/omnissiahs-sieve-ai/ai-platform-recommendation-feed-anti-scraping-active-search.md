| 信息类型          | AI 理解能力 | 自动获取难度  | 真正瓶颈         |
| ------------- | ------- | ------- | ------------ |
| 网页正文/标题       | 很强      | 低       | 几乎没有         |
| 点赞/收藏/作者/发布时间 | 很强      | 低～中     | 动态页面/API     |
| 评论            | 很强      | 中～高     | 无限滚动、折叠、登录   |
| 图片            | 很强      | 低～中     | 要逐张提取        |
| 视频画面          | 很强      | 中～高     | 下载/抽帧/上下文长度  |
| 视频语音          | 很强      | 中～高     | ASR 转写       |
| 弹幕            | 很强      | 中       | 平台接口         |
| 直播            | 能       | 很高      | 实时采集         |
| 私域/登录内容       | 能理解     | 很高      | 权限、Cookie、风控 |
| 平台推荐流内容       | 能理解     | **非常高** | 反爬、账号风控、动态加载 |

真正的问题：

不是ai理解不了视频，而是视频需要先被转成适合ai处理的信息。视频可以通过语音转文字、关键帧抽取、ocr和多模态分析解决，不需要像人一样把每一帧都完整看完。比如一个10分钟视频，可以完整转录音频，再每隔几秒抽一张关键帧，同时对场景变化和重要片段额外抽帧，这样就能把视频内容压缩成字幕、关键画面和结构化信息，成本远低于逐帧分析。所以视频本质上只是工程和算力问题。

**真正的硬伤是封闭平台的数据获取。**&#x5C0F;红书、抖音、instagram、tiktok这类平台不会愿意让机器大规模抓取内容，因此会遇到登录、cookie、验证码、接口签名、动态加载、限速、设备指纹、账号风控和封禁等问题。ai本身完全能判断一条内容有没有价值，真正困难的是怎么稳定拿到几百、几千甚至几万条内容。另一个更大的问题是信息量爆炸。如果一次抓到几万甚至几十万条内容，不能让ai全部深度分析，那样成本太高。

**正确做法**：应该是分层筛选：先用标题、正文、互动量和关键词做低成本初筛，再筛作者质量，再分析评论和视频字幕，最后只对极少数高价值内容做深度分析和交叉验证。也就是说，真正应该做的不是“让ai把整个互联网都看一遍”，而是建立一个信息采矿漏斗：先低成本扫海量内容，再把算力集中在最有价值的0.1%上。claude抓到了文本、图片、评论和视频处理难度不同这一点，但低估了两个更关键的问题：视频其实可以通过语音转写和抽帧解决，而**平台访问限制和海量信息筛选才是真正决定这个系统能不能规模化运行的核心**。

**为什么ai获取推荐流的内容极度困难**：推荐流不是被ban了，而是ai或脚本如果高强度自动刷推荐流，很容易被平台识别成机器人，从而触发验证码、限流、踢登录甚至封号。原因是抖音、小红书这类平台的**推荐流本身就是核心数据资产**，正常用户的行为通常比较随机，比如停留时间不同、偶尔点赞、偶尔退出，而自动化程序往往会连续翻页、固定间隔打开内容、短时间读取大量帖子和评论，这些行为特征很容易被风控系统识别。真正危险的不是ai能不能理解推荐流，而是能不能长期稳定地批量获取推荐流。如果只是像真人一样看几十条，一般问题不大，但如果一次自动刷几百甚至几千条，风险就明显上升。

**另辟蹊径：主动搜索流**：我认为搜索流其实比推荐流更重要，因为真正需要的是先用关键词找到几十到几百条候选内容，再让ai筛选最有价值的内容，继续进入作者主页、相关帖子和评论区深挖，而不是无止境地刷推荐页。这样既省算力，也更不容易触发平台风控。所以推荐流最好作为辅助入口，主流程应该是关键词搜索→初筛→深挖优质内容→追踪优质作者→继续扩展相关内容。这样才是最稳定、最有效率的方案。
